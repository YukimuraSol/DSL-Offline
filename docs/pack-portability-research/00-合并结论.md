# 整合包「适配性」调研 — 合并结论

日期：2026-10-24　范围：DSH Pack Launcher（D:\dsh-lch）　方法：三个独立只读调研员，互不重叠，结论交叉校验

---

## 一、三条贯穿三份报告的共同结论

### 1. 包本身是自洽的，但链接是绝对路径

整包实测 **150 条 reparse point**，目标**全部在包内**（outside = 0），这点是好消息。代价：

- 110 条位于 profiles/<id>/.dsh-launcher-plugin-bodies/<插件>/node_modules/
- 19 条位于 profiles/<id>/node_modules 顶层
- 目标形如 D:\DSH Pack Launcher\dsh-packs\...\profiles\node_modules\@deepseek-ai\...

路径一变：旧路径不存在 → 悬空，插件 cannot resolve；旧路径仍在 → **静默指向旧副本**，改新副本无效。

### 2. 自检看不见这批链接，所以「自检通过」不等于「能搬家」

electron/pack-verify.ts:715-741 的 readNodeModules：

- 只遍历 node_modules **顶层**，不递归（pack-verify.ts:724）
- 跳过以 . 开头的目录

于是 .dsh-launcher-plugin-bodies 整棵目录不在扫描范围内，那 110 条 junction **从未被检查过**。

### 3. 重建链接的代码已经存在，只是没接到「搬目录」这条路上

- 导入路径：pack-snapshot.ts:930-957（建链接）、:983-1029（rebuildBodyGates 重建门层）
- 搬目录路径：**没有任何对应步骤**

一句话：包该带的都带了（内核 + 插件本体 + 相对依赖），真正断的是**绝对路径 junction**，以及**没人校验的声明版本 / 平台架构**。

## 二、流程成本的真相：不是文件大，是「导出要 agent 帮忙」

- 导出对话框里**没有导出按钮**（PackExportDialog.tsx:46-94），只有「复制提示词」
- 真正的导出实现在 pack.ts:2024，渲染层也包了 store.exportPack（use-launcher-store.ts:1146-1155）——**没有 UI 调用它，是死路**
- 「接管已有文件夹」：IPC（ipc.ts:1146-1151）、preload（preload.ts:172）、实现（pack-adopt.ts:95-141）全齐，src/ 里**零调用**
- 应用内导入（解压 + 重建门层）实测基准：8 句柄解压 16,490 文件 15.3 秒，外推 9.6 万文件约 90–150 秒
- 「复制搬家提示词」：13 万文件 / 5.6GB 由 agent 串行搬 + 逐条重建 junction，**最慢**

## 三、三个会造成数据损失的硬伤

### ① profile.yaml 的 name 会让导入静默丢 profile

- 快照导入把 profile.yaml 的 name 直接当 profile 目录 id（pack-snapshot.ts:763-764）
- readProfile 对不存在的 profile 只返回 initialized:false / 0 插件，**不抛错**（profile.ts:92-105）
- 结果：导入报「成功」、state:'complete'，包里却没有那个 profile
- 本机活样本：profiles/dsh-origin-3080/profile.yaml 是 name: major place，目录却叫 dsh-origin-3080

### ② 导入失败不回滚 activePackId

- pack.ts:1470-1475 先改 settings 的 activePackId/profileName
- 解压抛错只删目录 + 删记录（pack.ts:1517-1522），settings 仍指向已被删除的包

### ③ 剔除名单有洞，残留备份常驻

- 剔除判据：名字含 backup / 含 .bak- / 以 .bak 结尾（pack-snapshot.ts:155-161）
- .retired-* / .removed-* **不剔，整份进包**
- profiles/node_modules.bak-stage2-20261023：30,519 文件 / 715MB，占该包文件数 15%，导出会被剔但仍在盘上、仍被每次扫描
