## 二、不可移植清单（实测）

### 1) junction —— 真正的问题

- origin **110 条**、fallback **31 条**
- 全部位于 profiles/<id>/.dsh-launcher-plugin-bodies/<插件>/node_modules/ 下
- Target 是**绝对路径**，且**全部指向包内**（inside = 110 / outside = 0）
- 例：...\\@deepseek-ai\\dsh-settings -> D:\DSH Pack Launcher\dsh-packs\dsh-fallback-4000\profiles\node_modules\@deepseek-ai\dsh-settings
- 生成者：pack-snapshot.ts:1014 symlink(bodyPath, ..., 'junction')
- 后果：旧路径不存在 → 悬空、插件 cannot resolve；旧路径仍在 → 静默指向旧副本
- 另：profiles 一层与 profiles/node_modules 前两层 **0 条**（只有更深处有）

### 2) .bin shim —— 不是问题

dsh.cmd / dsh / dsh.ps1 / cordis.cmd 全是 %dp0% / $basedir **相对**写法。
但包里 **没有 node.exe**（Test-Path = False），shim 会回落到 PATH 上的 node。

### 3) 配置里的绝对路径 —— 只有 1 处

- remote-web-ui-tunnel-child.json:3 的 cloudflared 全路径
- 其余顶层 + profile 层的 json/yml/yaml 盘符扫描 = **0 处**
- profile package.json 的 19 条依赖全是相对 file:./.dsh-launcher-plugin-bodies/...

### 4) 运行时不在包里

node 只在启动器侧：%APPDATA%\dsh-launcher\dsh-runtime\versions\0.2.0-rc.2\node_modules\.bin\node.exe（88MB），
注入点 runtime.ts:416-419 → **包不自包含**。

### 5) 启动器侧的绝对路径

- settings.json：dshInstallPath / dshHome / workspace / launchExecutable / packsRoot 全是 %APPDATA% 绝对路径
- packs.json：homePath 是绝对路径（且第 3 条 web 记录至今无 homePath，会被 instances.ts:484 跳过）
- instances.json：端口 3080 / 4000 / 3081

### 6) sessions

按绝对 cwd 分桶（--D-cursor~7F16...-- 等 3 桶），但 sessions/index.db（122,880B）盘符扫描 0 条
→ **sqlite 本身可移植**，桶名可移植性另说。

### 7) 机器指纹

- .anonymous-user-id 是 36 位 UUID
- .credentials.yaml 是 refs + records(secret/id/token)，**非硬件绑定**
- remote-web-ui-devices.json 内容未核实

### 8) 包必须待在 packsRoot 内

home-scope.ts:32-41：包被拷到 packsRoot 之外就「不被认领」，删除/回滚会被拒绝。
