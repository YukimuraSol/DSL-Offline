## 二、五条链路

### A. 导出为整合包 —— 启动器不执行导出，只发一段提示词

1. 包行点「导出为整合包」图标（SettingsView.tsx:398-404）
2. PackExportDialog 打开，后台取默认导出目录与 exe 路径
3. 对话框只有四样：摘要条、**复制提示词**、导出目录行、自检按钮（PackExportDialog.tsx:46-94）
   **没有任何「开始导出」按钮** —— 文件头注释写明「打包交给 agent，启动器只给提示词」
4. 用户把提示词粘进 agent 会话；agent 执行 <exe> --export <包id> "<目录>\<包名>.zip"（prompts.ts:216-218）
5. 命令跑不通时 agent 自己打 zip，并补三件事：生成 dsh-snapshot.json、剥 settings.yaml 密钥字段、把 file:/link: 本体收进 .dsh-launcher-plugin-bodies（prompts.ts:247-257）
6. agent 跑 <exe> --verify "<zip>"（prompts.ts:220-222），退出码 0/1/2
7. 对话框「自检」可对家目录跑同一套六条

- 手动改文件：用户不手改，但整条链路正确性押在 agent 身上
- 失败恢复：**没有**。无导出任务状态、断点、重试
- 另：真正的导出实现存在（ipc.ts:1051-1073 → pack.ts:2024），渲染层包了 store.exportPack（use-launcher-store.ts:1146-1155），**无任何 UI 调用 —— 死路**

### B. 导入整合包 —— 唯一全程在应用内、无需 agent 的链路

1. 点「导入整合包」（SettingsView.tsx:278-280），或把 zip/dspack 拖到列表区
2. pickPackFile → packs:analyze-import（ipc.ts:1014-1017），只读 zip 中央目录，此时不写盘
3. PackInstallDialog preview：可改包名、勾选组件
4. 确认 → packs:import（ipc.ts:1019-1049）：再 analyze → 缺 DSH 版本先装 → packManager.importPack
5. 快照分支（pack.ts:1427-1515）：建目录 → 写 record state:'partial' → **先改 settings 的 activePackId/profileName**（:1470-1475）→ extractSnapshot（解压 + 重建 links + rebuildBodyGates）→ readProfile → record 改 complete
6. 导入瞬间顺手跑一次 verifyPackHome（ipc.ts:1037-1047），有 fail/warn 自动弹自检对话框
7. 用户点电源启动，首次启动绑端口

- 手动：无
- 失败恢复：**有坑** —— 解压抛错只删目录 + 删记录（pack.ts:1517-1522），**不回滚第 5 步写进 settings 的 activePackId**，settings 指向已删包

### C. 复制搬家提示词 —— 文档式搬包，成本最高

1. 点标题行「复制搬家提示词」（SettingsView.tsx:272-274）
2. 前端取 packsRoot 与 exe 真路径，拼全文写剪贴板（SettingsView.tsx:242-260）
3. 用户粘给 agent；agent 先出规划，等用户回「开始」（prompts.ts:90-91）
4. agent 按第三节结构落成 <packsRoot>\<目录名>\，遵守 8 条硬规矩（全相对路径、删旧 junction 重建、删 .modules.yaml/.pnpm-workspace-state-v1.json/.package-map.json、不跑 pnpm install）（prompts.ts:93-146）
5. agent 跑 --verify，再人工核 6 项，把最终结构列给用户（prompts.ts:155-182）
6. 用户不用点按钮：下次 listPacks 自动收编（pack.ts:1002-1060）

- 等待：复制 13 万+ 文件 / 5.6GB + 逐 junction 重建
- 手动：名义上 agent 改，实际用户验收「是否按 8 条改了」
- 失败恢复：**无**，重来一遍就是再搬 5.6GB

### D. 接管已有文件夹 —— UI 上没有入口

- 能力齐全：IPC packs:adopt-folder（ipc.ts:1146-1151）、preload adoptPackFolder（preload.ts:172）、实现 pack-adopt.ts:95-141（只写 packs.json，不碰磁盘）
- 但 src/ 里**零调用**（只有 types.ts:1518、demo-api.ts:2039 两处声明）；pickPackFolder 同样死掉
- 用户唯一替代路径：手动把文件夹摆进 packsRoot，等 autoAdoptPacksRootDirs 收编（pack.ts:1002-1060）
- 收编判据：目录名过 isSafeProfileName、不是 .deleting-*、有 profiles/<id>/package.json
- id 必须等于已有 profile 目录名，撞名报错要求改名（pack-adopt.ts:120-124）
- 收编进来的外部目录，删包会被 home-scope.ts:44-47 拒绝（防误删用户 ~/.dsh）

### E. 新建实例

1. 点「新建实例」→ 输入名（ASCII）+ 选本机已装 DSH 版本
2. packs:create-blank（ipc.ts:1167）→ seedPackHome：只建 profiles/<id> + 核心 bundle + profile.yaml，**不带 node_modules**
3. 之后必须启动一次才算真正可用

- 秒级，无手动步骤；失败抛错进吐司，是否留空目录未核实

### F. 附件

- 行内「附件」按钮 → openPackExtras → 打开/创建 <家目录>\extras\
- 纯人工，列表只显示「附件 N」计数

## 三、时间成本主要花在哪

| 环节 | 源码注释实测基准 | 外推到本机 96k 文件 / 2.0GB |
|---|---|---|
| 扫描家目录 | 16,490 文件 0.37s（32 并发 stat） | ≈2–5 s |
| 打 zip（level 1，<1KB 与二进制 store） | 16,490 文件 / 392MB → 6.6s | ≈40–90 s（未实测） |
| 解压快照 | 16,490 文件：单句柄 25.3s / 4 句柄 19.7s / 8 句柄 15.3s / 16 句柄 19.0s | ≈90–150 s（按 8 句柄外推，未实测） |
| 重建 110 条 junction + body gates | 毫秒级 | 可忽略 |
| 缺 DSH 版本时补装 | 取决于是否下载 | 可能几分钟（未实测） |
| 搬家提示词（C） | 无并发、agent 逐文件 | 13 万文件 / 5.6GB，**十几分钟到小时级**（未实测） |

**结论：时间大头是「文件数量 × 单文件开销」，不是总体积。**
应用内导入已做过并发优化，单包约 1–3 分钟；搬家提示词那条纯串行，是全流程最贵环节。
隐形拖时间项：profiles 里 715MB / 30,519 文件的残留备份目录 node_modules.bak-stage2-20261023。

## 四、流程成本主要是哪几步手工操作

1. 导出/搬家都不是按钮，是「复制提示词 + 交给 agent」：用户要自己开 agent 会话、粘贴、等、验收
2. 目录名/包名规则要用户记：ASCII、首字符字母数字
3. 迁移后 junction 必须人工确认重建，否则 19 个插件门全断
4. 接管没有 UI 入口，只能手动摆文件夹
5. 失败即重来：导入失败留下 settings 指向已删包；搬家失败再搬 5.6GB

## 五、「复制搬家提示词」的出处与要求

- 出处：src/lib/prompts.ts:20-186 的 migratePrompt(dshHome, packName, packsRoot, launcherExe)；入口 SettingsView.tsx:242-260（名称故意传空串，让 agent 先问用户）
- 同族：prompts.ts:201-282 的 exportPrompt
- 它要求：
  1. 产出物是**文件夹**（不是 zip），落在 <packsRoot>\<目录名>（prompts.ts:39-40）
  2. 先出规划，等用户说「开始」（:90）
  3. 按固定结构落盘：家目录级 cordis.patch.yml/package.json/AGENTS.md；profiles\node_modules（内核）；profiles\<目录名>\{package.json, cordis.patch.yml, profile.yaml, node_modules(只有门), .dsh-launcher-plugin-bodies}；以及 sessions / dsh-session-archive / attachments / storages / 插件状态目录 / skills / .agent-presets / extras（:93-115）
  4. 8 条硬规矩：源环境只读、全相对路径、本体拷进 bodies、spec 改 file:./.dsh-launcher-plugin-bodies/<名>、**目标副本的 junction 全删重建**、删 pnpm 三个簿记文件、不跑 pnpm install（:130-145）
  5. 收尾自清 + --verify + 人工核 6 项 + 列最终结构（:155-182）
  6. 承诺「启动器下次启动自动扫到」（:182-184）—— 这条是真的（pack.ts:1002-1060）

## 六、自检（onVerify）检查了什么、漏了什么

入口：包行「自检」→ App.tsx:119-126 → packs:verify（ipc.ts:1073-1082）→ verifyPackHome（pack-verify.ts:475）
规则表 pack-verify.ts:83-90，六条：

1. 清单与目录对得上（package.json 每条 dependency 在 node_modules 下有目录 + profile 结构完整）
2. 本体是否留在包外（残留绝对 file: / link:）
3. node_modules 顶层链接目标是否在包内
4. dsh.profile.bundles 每个插件入口文件存在
5. profile.yaml 的 dshVersion 与本机 runtime/kernels/<ver> 比对
6. 每个插件依赖按 Node 解析顺序可解析 + 插件源码里 ~/.dsh/<名> 目录存在

漏掉的（都可能让「自检通过」的包换机后不能用）：

- settings.yaml 是否存在/可解析 —— 本机这个包**根本没有**（只有 97 字节的 settings.yaml.imported）
- 凭据可用性
- sessions / attachments / storages / skills / presets / extras 完整性
- profile.yaml 的 name 与 profile 目录名是否一致（第 1 条只比 package.json 的 name）
- junction 是否**仍指向本包的旧绝对路径**（第 3 条只判「在包内」，旧路径在包内就算过）
- 文件里残留的绝对路径字符串（插件源码、data/、config/）
- ACL/权限、长路径（只在导入时有 longPaths 报告，pack.ts:1485-1487）
- .bin shim 内容
- 内核**能不能真跑**（只比目录名）
- 端口占用、首次启动是否成功

## 七、三个顺带发现的硬伤

### ① 搬家提示词教的 profile.yaml name，启动器既读不出、导入时还会炸

- 提示词说「显示名写进 profile.yaml 的 name:，中文完全可以」（prompts.ts:87/104/122）
- 但读取时 name 必须过 isSafeProfileName（纯 ASCII），否则**回落成目录名**（profile-service.ts:119），写回时更被强制改成目录名（:256）
- 更糟：快照导入把 profile.yaml 的 name 直接当 profile 目录 id（pack-snapshot.ts:763-764），解压路径映射也用它（:1036-1042）
- readProfile 对不存在的 profile 只返回 initialized:false / 0 插件，**不抛错**（profile.ts:92-105）
- → 导入「成功」、state:'complete'，但包里没有那个 profile
- 本机活样本：name: major place，目录 dsh-origin-3080 —— 导出再导入就会踩
- 纯中文名更直接：assertMeaningfulPackName 会抛「整合包名称需包含字母或数字」

### ② 两个提示词对 settings.yaml 的说法互相矛盾

- 导出提示词要求 zip 根必须含 settings.yaml（prompts.ts:255）
- 搬家提示词结构清单完全没提（prompts.ts:93-115）—— 本机包也确实没有
- 按搬家提示词做出的包，导出时会缺 settings.yaml

### ③ 备份剔除有盲区

- 判据：名字含 backup、含 .bak-、或以 .bak 结尾（pack-snapshot.ts:155-161）
- .retired-* / .removed-* **不剔，整份进包**
- profiles/node_modules.bak-stage2-20261023（30,519 文件 / 715MB）导出时被剔，但仍占磁盘、仍参与每次扫描
